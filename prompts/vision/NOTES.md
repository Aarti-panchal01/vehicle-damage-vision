# Prompt version notes

Every version is a separate file. Old versions are never edited; a change means a new file. The repair prompt (`repair_v1.md`) is shared by all versions and only runs when a reply fails validation.

| Version | Team-plan strategy | What changed | Why |
|---|---|---|---|
| `v0_baseline` | (baseline) | Only "Describe the damage in this image." | Lower bound. Shows what the repair step alone can recover from free text. |
| `v1_structured` | Zero-shot | Assessor role, the allowed part/type/severity strings, the left/right convention, rules (visible damage only, lower confidence when unsure, empty list when undamaged, decals are not damage), quality flags, and an exact JSON template. Run twice: plain, and with the API's structured-output schema (`+schema`). | Gives the model the contract it must fill. The `+schema` run tests whether API-side enforcement adds anything over a well-specified prompt. |
| `v2_fewshot` | Few-shot | v1 plus two worked examples from the dev split: a rear-corner multi-damage photo (dev_03) and an undamaged car (dev_10). | Shows the expected granularity (one entry per part and type) and that "no damage" is a valid answer. Two examples, not three, because Groq takes at most 3 images per request. |
| `v3_cot` | Chain-of-thought | v1 plus a 3-step procedure (orientation, panel by panel, mapping) written into an `analysis` field before the damages. | Tests whether visible step-by-step reasoning improves part and side accuracy. The reasoning stays inside the JSON so validity is not hurt. |
| `v4_best` | Few-shot + targeted rules | v2's examples (re-written with a short analysis) plus: explicit rules to convert photo-left/right into car-left/right for front, rear, side and corner views; door-handle rule for front/rear doors; definitions for each damage type ("glass is always glass_shatter, lamps are always lamp_broken"); the severity rubric with "do not round up"; and a self-check that re-reads every left/right part against the orientation. | Built from the v1-v3 failures on Gemini (see docs/role1/RESULTS.md): (1) sides were mirrored on 3 to 4 of the 15 damaged photos in every version, including v3, whose own reasoning said "rear and left side" for a rear-right view; (2) severity was one step too high 8 to 9 times and never too low; (3) cracked windshields were labelled `crack` and torn plastic bumpers `dent`. |
